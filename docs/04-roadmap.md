## M1 · 「真的能用」（4–6 周）

目标：让一个人愿意把它当作**每天打开**的工具。

### 1.1 云厂商真实接入（P0）

| 厂商 | 方式 | 状态 |
| --- | --- | --- |
| 阿里云 | RPC OpenAPI + Signature 1.0（Rust 手写签名） | ✅ 已完成 |
| AWS | Query API + SigV4（Rust 手写签名，对齐官方测试向量） | ✅ 已完成 |
| 腾讯云 | TC3-HMAC-SHA256 手写签名 | ⛔ 待做 |

验收：

- [ ] 用真实只读 AK 拉到实例列表，字段与 Mock 一致。
- [ ] 分页（阿里云 100/页、AWS NextToken）正确。
- [ ] 限流（Throttling）有退避重试，UI 有明确错误提示。
- [ ] AK 失效时提示「重新绑定」，而不是空白列表。

### 1.2 卡包体验补齐（P0）

- [ ] 卡片详情页：账单明细、按月筛选、按商户聚合。
- [ ] 还款日提醒（本地通知，Tauri `notification` 插件）。
- [ ] 账单周期自动推算（已实现 `nextDueDates`，接 UI）。
- [ ] PDF 账单解析（先支持招商/中信两种模板）。
- [ ] 手动补录交易。

### 1.3 存储升级（P1）

- [ ] Tauri 侧改用 SQLite（`tauri-plugin-sql`），localStorage 仅保留 Web 预览。
- [ ] 数据迁移脚本 + 回滚路径。
- [ ] 数据库文件整体加密（SQLCipher 或应用层加密）。

### 1.4 同步增强（P1）

- [ ] 冲突快照：落败版本存 7 天，设置页可查看/恢复。
- [ ] 后台自动同步（启动时 + 每 30 分钟 + 网络恢复时）。
- [ ] 设备管理页：查看所有设备、吊销。
- [ ] 同步进度与错误可视化。

## 风险清单

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 银行 CSV 格式频繁变动 | 高 | 中 | 解析器容错 + 用户可手工补录；建立格式反馈入口 |
| 云厂商 SDK 版本/签名差异 | 中 | 高 | 适配器隔离；每个厂商单独 e2e（用只读测试账号） |
| 移动端 WebView 兼容问题 | 中 | 中 | 尽早做 iOS/Android 真机验证，别等到最后 |
| Tauri 移动端生态不成熟 | 中 | 高 | 关键能力（钥匙串/通知/SQLite）先做 spike，失败则退回原生壳 |
| 用户不愿自建服务器 | 高 | 中 | 同步是可选功能；离线单机也完整可用 |
| 合规（若做托管同步） | 低 | 高 | 暂不做托管；如要做，先做 PIPL 评估 |

## 里程碑验收（DoD）

每个里程碑必须满足：

1. 所有新增逻辑有单测；同步相关必须有 e2e。
2. `pnpm typecheck && pnpm test && pnpm build` 全绿。
3. 至少在一台真机（桌面或手机）上跑通核心路径。
4. 更新 README 的「当前状态」表与本文档。
