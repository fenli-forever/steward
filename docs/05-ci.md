# 05 · CI 与多端打包

两条流水线，分工明确：

| 工作流 | 触发 | 目的 | 时长（参考） |
| --- | --- | --- | --- |
| `.github/workflows/ci.yml` | push main / PR / 手动 | 类型检查、79 个单测、前端构建、`cargo check` | 4–6 分钟 |
| `.github/workflows/build.yml` | 手动 / 打 `v*` tag | 产出 macOS / Windows / Linux / Android / iOS 安装包 | 15–25 分钟 |

## 1. 日常门禁：ci.yml

两个 job：

- **web**：`pnpm typecheck` → `pnpm test` → `pnpm build`。注意 `@steward/sync` 的测试会 import
  `@steward/core` 的构建产物，所以流程里先跑 `pnpm --filter @steward/core build`。
- **rust**：在 Ubuntu 上装 `libwebkit2gtk-4.1-dev` 等 Tauri 依赖，跑 `cargo fmt --check` 与 `cargo check`。

为什么 Rust 检查单独一个 job：仓库里 `src-tauri` 之前从未编译过（开发机没装 Rust），
这个 job 是唯一能保证「Rust 侧没有编译错误」的地方。`tauri::generate_context!` 在编译期读
`frontendDist`，缺 `dist` 会直接失败，所以步骤里先构建前端。

## 2. 打包：build.yml

```
test ──┬── macos    → .dmg（universal，arm64 + x64）
       ├── windows  → .exe（NSIS）+ .msi（WiX）
       ├── linux    → .AppImage + .deb
       ├── android  → debug .apk（arm64 + armv7）
       ├── ios          → 模拟器 .app（zip，装不了真机）
       ├── ios-unsigned → 未签名真机 .ipa（免费 Apple ID 自签用）
       └── ios-ipa      → 签名 .ipa（需 Apple 证书，默认跳过）
              └── release（仅 tag）→ 草稿 Release 附带全部产物
```

### 产物下载

- 手动跑：Actions → build → 选中一次运行 → 页面底部 Artifacts。
- 打 tag：`git tag v0.1.0 && git push origin v0.1.0`，会创建一个**草稿 Release**，产物挂在里面。

| Job | 产物 | 能直接用吗 |
| --- | --- | --- |
| macOS | `Steward_0.1.0_universal.dmg` | ✅ 双击安装（首次打开可能需右键 → 打开） |
| Windows | `Steward_0.1.0_x64-setup.exe` / `.msi` | ✅ 双击安装 |
| Linux | `Steward_0.1.0_amd64.AppImage` / `.deb` | ✅ `chmod +x` 运行 / `dpkg -i` |
| Android | `app-universal-debug.apk` | ✅ 传到手机安装（debug 签名） |
| iOS | `steward-ios-simulator.zip` | ⚠️ 只能拖进模拟器，装不了真机 |
| iOS（配了证书） | `steward-ios.ipa` | ✅ 可装在登记过 UDID 的设备上 |
| iOS（未签名） | `steward-ios-unsigned.ipa` | ✅ 用 Sideloadly/AltStore 自签后可装 |

### 为什么默认不签名

签名需要私钥，私钥只能放 GitHub Secrets，仓库里不能有；而这套仓库刚起步，还没有证书。
所以默认产出「可运行但未正式签名」的包：

- macOS：用 ad-hoc 签名（`APPLE_SIGNING_IDENTITY: "-"`），避免 Apple Silicon 下载后提示「已损坏」；
  但没有公证，首次打开仍需右键 → 打开。
- Android：debug 签名，可安装，不能上架。
- iOS：模拟器包，不需要证书；真机 IPA 见下一节。

## 2.5 iOS：IPA 到底能不能装

**IPA 只是一个 zip 包，能不能装完全取决于「签名类型 + 设备是否在白名单」**，跟文件格式无关。
同一个 `.ipa`，在登记过的手机上能装，换一台就提示「无法安装此 App」。

| 签名类型 | 需要 | 能装在哪 | CI 可行 |
| --- | --- | --- | --- |
| Development（开发） | $99/年账号 + 设备 UDID 登记 | 仅登记过的设备 | ✅ 本仓库已支持 |
| Ad Hoc | $99/年 + 每年 100 台 UDID | 仅登记过的设备 | ⚠️ 需 Xcode 手动归档导出（Tauri 2.12 CLI 未暴露 ad-hoc 导出） |
| TestFlight | $99/年 + App Store Connect | 测试人员（内部 100 人免审） | ✅ `--export-method release-testing` |
| App Store | $99/年 | 所有人 | ✅ `--export-method app-store-connect` |
| 企业 In-House | $299/年 | 任意设备 | ❌ 不推荐，见下 |
| 免费 Apple ID | 无 | 仅 Xcode 直连的一台设备，7 天失效 | ❌ 无法 CI |

### 启用「开发签名 IPA」

1. Apple Developer 后台建一个 App ID，**Bundle ID 必须是 `com.steward.app`**（与 `tauri.conf.json` 一致）。
2. 在 Devices 里添加手机 UDID，创建 Development 证书（导出 `.p12`）与 Development Provisioning Profile。
3. 转成 base64 后写入仓库 Secrets：

   ```bash
   base64 -i cert.p12 | pbcopy                 # → IOS_CERTIFICATE
   base64 -i profile.mobileprovision | pbcopy  # → IOS_MOBILE_PROVISION
   ```

4. 仓库 Settings → Secrets and variables → Actions：
   - Secrets：`IOS_CERTIFICATE`、`IOS_CERTIFICATE_PASSWORD`、`IOS_MOBILE_PROVISION`
   - Variables：`ENABLE_IOS_SIGNING` = `true`（不设就跳过这个 job，不会报错）
5. 手动触发 build，下载 `steward-ios-ipa`。

### 怎么装到手机

- **Apple Configurator 2**（Mac App Store 免费）：把 `.ipa` 拖到已连接的设备上，最稳。
- **Xcode** → Window → Devices and Simulators → 拖入。
- **OTA 分发**（蒲公英 / Diawi / 自建 itms-services）：上传 IPA，用 Safari 打开安装页。
  注意 iOS 需要在「设置 → 通用 → VPN 与设备管理」里信任开发者证书。

设备没登记 UDID 会直接失败，这是 Apple 的限制，不是打包问题。

### 想给多个人测试 → 用 TestFlight

把构建命令换成：

```yaml
run: pnpm tauri ios build --export-method release-testing --ci
```

然后在 CI 里用 App Store Connect API Key（`APPLE_API_ISSUER` / `APPLE_API_KEY` / `APPLE_API_KEY_PATH`）
上传构建。内部测试员最多 100 人、不需要审核；外部测试员首个构建要审核。

### 为什么不建议企业证书

- 企业证书（In-House）只允许分发给**本组织员工**，对外分发违反 Apple 开发者协议，证书随时可能被吊销；
  一旦吊销，所有已安装的 App 会直接打不开（对用户来说是数据恐慌，不只是不能更新）。
- 这个 App 管银行卡、云厂商密钥，来源不明或随时失效的签名是不可接受的风险。

## 2.6 不花钱装到 iPhone：未签名 IPA + 免费 Apple ID

不想买 $99 开发者账号也有路走：CI 出一个**未签名真机 IPA**，你在本地用自己的 Apple ID 重签。

`build.yml` 里的 `ios-unsigned` job 就是干这个的，**不需要任何证书**：

```bash
pnpm tauri ios build --debug --target aarch64 --ci --no-sign --archive-only
```

> 关键就是 `--no-sign`（跳过签名）和 `--archive-only`（只产 archive，跳过必须签名的导出步骤）。
> 不用改 Xcode 工程文件，也不用伪造证书。

产物 `steward-ios-unsigned.ipa` 已验证：arm64 真机架构（不是模拟器）、未签名、
`MinimumOSVersion 15.0`、Bundle ID `com.steward.app`。

### 装到手机（macOS 或 Windows 都行）

1. Actions 页面下载 `steward-ios-unsigned`。
2. 用 **[Sideloadly](https://sideloadly.io/)**：
   - 数据线连上 iPhone，选择设备；
   - Apple ID 填你的（免费账号即可，会提示输入密码做一次签名）；
   - 把 `.ipa` 拖进去 → Start。
3. 手机上：设置 → 通用 → VPN 与设备管理 → 信任你的开发者证书。
4. 打开 App。

**AltStore** 也可以，流程类似（需要 AltServer 常驻）。

### 免费账号的四个限制

| 限制 | 说明 |
| --- | --- |
| 7 天过期 | 到期后 App 打不开，重新签名装一次即可；**App 内的数据不会丢**（数据容器保留） |
| 最多 3 个 App | 同一 Apple ID 签名并存的自签 App 数量 |
| 必须线连/工具安装 | 不能像商店应用那样直接下载 |
| 部分能力不可用 | 推送、某些 entitlement 需要付费账号；Keychain 不受影响，密钥照常可用 |

如果只是自己用、能接受每 7 天重签一次，这条路完全够。
想省事就上 $99 开发者账号，走上面 2.5 的签名 IPA 或 TestFlight。

## 3. 接入正式签名

### Android（上架 / 正式分发）

1. 生成 keystore：

   ```bash
   keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   base64 -i upload-keystore.jks | pbcopy   # → Secrets.ANDROID_KEY_BASE64
   ```

2. 在仓库 Secrets 里加 `ANDROID_KEY_BASE64`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。

3. 在 `tauri android init` 之后、`android build` 之前插入两步（官方做法）：

   ```yaml
   - name: 写入签名配置
     working-directory: apps/app/src-tauri/gen/android
     run: |
       echo "keyAlias=${{ secrets.ANDROID_KEY_ALIAS }}" > keystore.properties
       echo "password=${{ secrets.ANDROID_KEY_PASSWORD }}" >> keystore.properties
       base64 -d <<< "${{ secrets.ANDROID_KEY_BASE64 }}" > "$RUNNER_TEMP/keystore.jks"
       echo "storeFile=$RUNNER_TEMP/keystore.jks" >> keystore.properties

   - name: 让 Gradle 使用上传密钥
     run: |
       python3 - <<'PY'
       # 在 app/build.gradle.kts 里插入 release signingConfig（模板默认没有）
       ...
       PY
   ```

   细节见官方文档：[Android Code Signing](https://v2.tauri.app/distribute/sign/android/)。

4. 把 `--debug` 换成 `--aab`（Play 商店）或 `--apk`（自建分发）。

### iOS（真机 / TestFlight）

需要 Apple 开发者账号，准备：

- `APPLE_CERTIFICATE`（.p12 的 base64）、`APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`（如 `Apple Distribution: Your Name (TEAMID)`）
- `APPLE_ID`、`APPLE_PASSWORD`（App 专用密码）、`APPLE_TEAM_ID`

然后把构建步骤改成：

```yaml
- run: pnpm tauri ios build --export-method app-store-connect
  env:
    APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}
    APPLE_CERTIFICATE_PASSWORD: ${{ secrets.APPLE_CERTIFICATE_PASSWORD }}
    APPLE_SIGNING_IDENTITY: ${{ secrets.APPLE_SIGNING_IDENTITY }}
```

参考：[iOS Code Signing](https://v2.tauri.app/distribute/sign/ios/)。

### macOS（公证后可直接双击打开）

- `APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD` / `APPLE_SIGNING_IDENTITY`
- `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID`（用于公证 notarization）

参考：[macOS Code Signing](https://v2.tauri.app/distribute/sign/macos/)。

### Windows（消除 SmartScreen 警告）

- `TAURI_SIGNING_PRIVATE_KEY`（可选，用于 updater）
- 代码签名证书走 Azure Trusted Signing 或 EV 证书，配置 `WINDOWS_CERTIFICATE` 等 Secret。

参考：[Windows Code Signing](https://v2.tauri.app/distribute/sign/windows/)。

## 4. 常见失败与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Android：`NDK not found` | 模板生成的 `ndkVersion` 与安装的不一致 | 确认 `NDK_HOME` 指向 `$ANDROID_SDK_ROOT/ndk/27.0.12077973`，或让 Gradle 自动下载（需先 `sdkmanager --licenses`） |
| Android：`Failed to find target with hash string 'android-35'` | 只装了 NDK 没装 platform | `sdkmanager "platforms;android-35"` |
| iOS：`error: unable to find utility "xcodebuild"` | runner 的 Xcode 未选中 | 加 `sudo xcode-select -s /Applications/Xcode.app` |
| iOS：模拟器包构建报签名错误 | `--target aarch64-sim` 以外的目标需要证书 | CI 里固定用 `aarch64-sim` |
| Linux：`webkit2gtk not found` | 依赖没装全 | 按 ci.yml 里的 apt 列表装 |
| macOS：`target not installed` | universal 需要两个 rust target | `rustup target add aarch64-apple-darwin x86_64-apple-darwin` |
| 打包时前端 404 | `frontendDist` 没构建 | 步骤里先 `pnpm --filter @steward/core build`，`beforeBuildCommand` 会自动 build 前端 |

## 5. 本地跑同样的命令

```bash
pnpm install --frozen-lockfile
pnpm --filter @steward/core build

# 桌面
cd apps/app && pnpm tauri build --target universal-apple-darwin   # macOS 通用包
cd apps/app && pnpm tauri build --bundles nsis,msi                # Windows

# Android（需 ANDROID_HOME / NDK_HOME / JDK 17）
cd apps/app && pnpm tauri android init --ci
cd apps/app && pnpm tauri android build --apk --debug --target aarch64 armv7

# iOS（需 Xcode）
cd apps/app && pnpm tauri ios init --ci
cd apps/app && pnpm tauri ios build --debug --target aarch64-sim
```

## 6. 计费（私有仓库才花钱）

GitHub 在 2026 年把 Actions 计费从「分钟数 × 倍数」改成了**按美元计的算力额度**：

| 计划 | 每月包含算力 |
| --- | --- |
| GitHub Free（个人） | $12 |
| GitHub Free（组织，本仓库所在） | $12 |
| GitHub Team | $18 |
| GitHub Enterprise Cloud | $300 |

单价：Linux 2 核 `$0.006/分钟`、Windows 2 核 `$0.010/分钟`、macOS `$0.062/分钟`。

换算到本仓库：

| 任务 | 平台 | 约耗时 | 约花费 |
| --- | --- | --- | --- |
| `ci.yml`（一次 push） | Linux ×2 | 8 分钟 | ≈ $0.05 |
| `build.yml` macOS | macOS | 12 分钟 | ≈ $0.74 |
| `build.yml` Windows | Windows | 10 分钟 | ≈ $0.10 |
| `build.yml` Linux | Linux | 6 分钟 | ≈ $0.04 |
| `build.yml` Android | Linux | 10 分钟 | ≈ $0.06 |
| `build.yml` iOS 模拟器 | macOS | 15 分钟 | ≈ $0.93 |
| **一轮完整五端打包** | — | ~50 分钟 | **≈ $1.9** |

结论：$12/月 大约够 **6 次完整打包**，日常 push 几乎不花钱（每次几分钱）。
超出后**会真实扣费**，除非在 Organization → Settings → Billing → Budgets 里设置
「Stop usage when budget limit is reached」。

省钱的三个办法：

1. **公开仓库**：标准 runner 对公开仓库免费、不限量（本项目代码里没有密钥，随时可以切）。
2. **自建 runner**：macOS 自托管 runner 不计费，代价是需要一台常在线的 Mac。
3. **只用 tag 触发打包**（本仓库默认如此），日常 push 只跑 `ci.yml`。

另外，artifact 存储单独计量（Free 500MB），所以所有上传步骤都设了 `retention-days: 7`；
Release 资产不占这个额度，正式产物请以 Release 为准。

## 7. 备注

- `src-tauri/gen/`（Android / iOS 原生工程）**不入库**，由 CI 每次 `init` 现场生成。
  好处是不会和 Tauri 版本漂移；代价是移动端构建每次多花 1–2 分钟。
- Rust 与 pnpm 都配了缓存；首次运行会慢，之后快很多。
- 仓库目前**没有配置 git remote**，推送到 GitHub 后 Actions 才会真正开始跑。
- 本机已验证：`cargo check` 通过、`tauri build` 生成 `Steward.app`；`.dmg` 制作需要 `hdiutil` 的磁盘镜像权限，
  在受限沙箱里会报 `hdiutil: create failed - 操作不被允许`，属环境限制，CI 的 macOS runner 不受影响。
